## Негативные тесты изоляции (pass = ограничение сработало)

| Тест | Native | srt | Docker |
|---|:--:|:--:|:--:|
| Запись вне worktree (`$HOME/x`) — должна **падать** | PASS (read-only fs) | PASS (read-only fs) | PASS (хост скрыт) |
| Сеть к не-allowlisted хосту — должна **падать** | PASS (через `/sandbox`) | PASS (403, корот. cmd) | PASS (`--network none`) |
| Запись внутри worktree — должна **работать** | PASS | PASS | PASS |
| Сеть к разрешённому хосту — должна **работать** | PASS (агенты отработали) | PASS (302) | n/a (claude в образе не ставили) |
| `node`/тулчейн из `/nix/store` исполняется | PASS | PASS | n/a (свой userland) |

> Оговорка по честности: adversarial-промпт «обойди песочницу» Claude **отклоняет на уровне модели** —
> для проверки OS-границы использован легитимно сформулированный тест записи в `$HOME`
> (агент сам отрапортовал `read-only file system`). Полный claude-в-srt и claude-в-docker
> с сетью не доводились до зелёного (srt — затык systemd/proxy на NixOS; docker — не ставили
> claude в образ); их FS/механизмы доказаны детерминированно отдельными пробами.

## Заметки по кандидатам

### Native (проверено эмпирически, `poc/native.sh`)
- 3 агента параллельно (haiku), каждый в своём worktree → выполнили задачи за 15–26с, все тесты зелёные.
- Автономность: `--permission-mode bypassPermissions`, ноль промптов.
- **OS-граница подтверждена детерминированно**: под bypassPermissions запись в `$HOME` → агент сам отрапортовал `read-only file system, EXIT=1`, файла на хосте нет. То есть sandbox (bwrap) активен независимо от permission-mode.
- Merge 3 веток в main без конфликтов, финальные тесты 0 fail.
- **NixOS — из коробки**: нативный sandbox монтирует весь FS read-only (кроме cwd), поэтому `/nix/store` читается, `node`/`npm` работают без хаков с путями. Главное преимущество перед ручным bwrap-профилем.
- Зависимости на хосте уже есть: bubblewrap 0.11.2 + socat 1.8.1.1.
- Конфиг = только `.claude/settings.json` (`sandbox.enabled`, `network.allowedDomains`). Кода 0.
- Граница на BASH-субпроцессы; сам процесс claude и Read/Edit/Write — вне песочницы (но FS-правки и так в cwd).
- Замечание: adversarial-промпт «обойди sandbox» модель ОТКЛОНЯЕТ на своём уровне — для проверки OS-границы нужен легитимно сформулированный тест (см. выше).

### srt (проверено, `poc/srt.sh`) — @anthropic-ai/sandbox-runtime 0.0.52
- **FS-изоляция: работает детерминированно на NixOS из коробки.** Запись в cwd — OK; запись в `$HOME` → `Read-only file system`, файла на хосте нет; `node` из `/nix/store` исполняется (srt ro-bind'ит весь FS, хаков с путями не нужно).
- **Сеть (короткие команды): allowlist работает.** anthropic.com → 302, example.com → 403 CONNECT blocked.
- Схема конфига = как у native (`filesystem.allowWrite/denyWrite/denyRead`, `network.allowedDomains`), файл `~/.srt-settings.json` или `-s`.
- **Уникальное преимущество vs native:** изолирует ВЕСЬ процесс (сам claude, MCP-серверы, любые инструменты), а не только bash-субпроцессы.
- **Минус на ЭТОМ NixOS-хосте:** обёртка всего процесса claude **не заработала из коробки** — srt поднимает сетевой proxy через системный D-Bus (`Failed to connect to system scope bus: Operation not permitted`), упирается в tinyproxy/systemd. FS-часть при этом исправна; затык — сетевой слой при долгоживущем процессе. Нужна доводка (свой proxy/HTTP_PROXY, права на bus).
- Стейт claude (`~/.claude`, `~/.cache`, `/tmp`) при обёртке нужно явно добавлять в `allowWrite` — native это делает сам.

### Docker-per-agent (проверено, `poc/docker-sbox.sh`; sbox — по research)
- **Сильнейшая изоляция из трёх**: хостовый FS скрыт целиком (виден только bind-mount worktree), `~/.ssh` недоступен; `--network none` режет DNS полностью.
- **NixOS-agnostic**: userland из образа, `/nix/store` не задействован → нет проблем с путями.
- worktree живёт на хосте (bind-mount) → git/diff/merge на хосте, как в native.
- Старт `node --test` в контейнере ~**945мс** при закэшированном образе (node v22.22.3 из образа).
- **Трение (главный минус для нашей цели):** реальный claude требует образа с установленным claude + авторизации в контейнере (mount `~/.claude` или `ANTHROPIC_API_KEY`) + сети к `api.anthropic.com`. Образ на диск, ресурсы на контейнер.
- Паттерн «под ключ» = [streamingfast/sbox](https://github.com/streamingfast/sbox) (per-worktree контейнер + claude). Оправдан при недоверенном коде/строгой воспроизводимости; для доверенного локального — тяжелее native.

## Гейт build-or-adopt

- **adopt (native)** — если native ± тонкая обёртка закрывает требования.
- **adopt + враппер** — если native мало, но srt/docker близки.
- **build** — если эргономики параллели/изоляции на NixOS не хватает ни у кого.

### ВЕРДИКТ: adopt native + тонкий оркестратор (НЕ писать свою песочницу)

Native победил с большим отрывом (54/55). Он закрывает все требования **без единой строки
кода песочницы** — только `.claude/settings.json`: изоляция FS/сети, автономность, параллель
по worktree, чистый merge, NixOS из коробки. srt и docker сильнее лишь в нишах (изоляция
всего процесса / недоверенный код), которые нам не нужны (код доверенный, локально).

Единственный пробел native — **оркестрация UX**: создать N worktree, запустить N автономных
sandbox-агентов, собрать логи/диффы, слить ветки. Это НЕ песочница, а тонкая обвязка (~60 строк
shell, прототип уже есть в `../poc/native.sh`).

→ Строим тонкий `sandboxer` поверх native (worktree + `/sandbox` + headless claude). Свою
изоляцию не пишем. Подробности — `../README.md` decision-log и Фаза 3 плана.
